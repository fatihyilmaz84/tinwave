Specific checks you asked for:
- **Snapshots.** The start snapshot is taken at TrackStarted and the end at TrackLeft. Each drain reads the engine counters once (mod.rs:585-594) and every event in that drain uses that reading. In a gapless hand-off, TrackLeft(A) and TrackStarted(B) come from the same `poll()` (engine.rs:722-731), so they share one boundary. The counters only grow (no store outside tests), so the subtraction cannot underflow and nothing is counted twice. For a requested load, `Controller::load` reads once in its pre-poll drain and once in the drain after the load. Audio played between consecutive readings goes to exactly one play. Any A frames that render after B's start reading count towards B, but only for about one callback, which is within the documented edge error.
- **Exclusive reopen.** The counters are shared and never reset, and the result is a ratio. The 44.1/96/44.1 kHz test covers it.
- **Queue.** At most 64 entries, oldest dropped first, drops counted (`a_consumer_that_never_collects_loses_the_oldest_and_it_is_counted`). The mutex is held only for a push or a swap. The queue lives on the controller thread, never in the audio callback. It is in memory only. The only log line is a `debug` with a queue item id. The values go nowhere else.
