# ADR 0005 — Audio backend: Symphonia decode, in-house playback engine, direct WASAPI output (cpal as fallback / other OSes)

- **Status:** Accepted (PO decision D-0003, 2026-11-02; from spike T-0003, report work/reports/T-0003/spike-1.md)
- **Date:** 2026-11-02

## Context

Spec section 7 requires gapless playback, reliable seek, output-device changes and "clear error recovery", and says to
choose the backend by a real-world test. `docs/rules/architecture.md` adds hard constraints: one playback thread, **no
allocation in the audio callback**, playback never blocks on DB/network/analysis. The signal catalog needs accurate
position (skip / seek / section signals), a volume hook (`VolumeChanged`, `SystemVolumeChanged`, `MuteToggled`) and
`ExclusiveModeToggled`. PO decision D-0001: Windows first.

The spike (`spikes/T-0003-audio-backend/`, throwaway) built one engine core and plugged three outputs into it, then
measured on **Windows 11 Pro 10.0.26200, AMD Ryzen 7 7800X3D, Rust 1.92 (release build), default endpoint "High
Definition Audio Device" (shared mix format 48 kHz / 2 ch / f32, device period 10 ms, minimum 2.67 ms)**.
Test material was generated by the spike: a 200 Hz to 12 kHz log sine sweep at -20 dBFS, 10 s long, split into two
files at frame `5*rate+777` (not aligned to any codec frame), in WAV 16/24/f32, FLAC 16/24, MP3 (LAME with and
without gapless tag), ALAC and AAC-LC, at 48 kHz and 44.1 kHz. Raw output is in `results/`.

## Decision

1. **Decode: Symphonia 0.6** (pure Rust, MPL-2.0), features `all` minus anything we do not need later. Used through a
   thin `TrackReader` (open, accurate seek, pull interleaved stereo f32) that also accepts an external gapless trim
   (`delay`, `valid_frames`).
2. **Engine core is ours, backend-independent** (`tinwave-playback`, about 400 lines in the spike):
   decoder thread -> lock-free SPSC ring (`rtrb`, 1 s of audio) -> `Renderer` running inside the OS audio callback.
   - Renderer contract: no allocation, no locks, no file/DB/network access. Verified: **0 heap allocations or frees
     inside `render()`** over 12 playback runs including seeks and volume changes (counting global allocator).
   - Software volume: `AtomicU32` target, linear per-block ramp, no zipper noise, no allocation.
   - Seek: control thread -> decoder thread command; decoder raises `flush_req`, the callback drains the ring and
     acks, decoder then seeks and refills. Landing is sample exact (see matrix).
   - Position: `frames consumed by the callback - output latency frames`, mapped to (track, frame) through track
     start marks written by the decoder. Gapless across tracks needs nothing special: the decoder simply opens the
     next file and keeps filling the same ring.
   - Device change: build a new ring + stream and send `Reconfigure{track, frame}` to the decoder (about 20 ms on
     real endpoints, resumes at the exact frame).
3. **Output behind a trait with per-OS modules** (already the shape in `architecture.md`):
   - **Windows: direct WASAPI** via the `wasapi` crate (MIT, thin wrapper over `windows`), event-driven, MMCSS "Pro
     Audio", shared mode by default and **exclusive mode** for `ExclusiveModeToggled`; `IMMNotificationClient` for
     default-device and device-state changes; `IAudioEndpointVolume` callback for `SystemVolumeChanged`.
   - **macOS / Linux / any OS without a native module yet: cpal** (Apache-2.0). cpal also stays available on Windows as
     a switchable fallback (it passed every gapless/seek/volume test the direct backend passed).
4. **Gapless metadata is a library-layer duty.** Symphonia trims MP3 delay/padding from the LAME/Xing tag (verified),
   and FLAC/WAV/ALAC are exact by construction. **Symphonia 0.6.1 ignores M4A edit lists and `iTunSMPB`**, so the
   scanner must read them (or the engine must) and store `GaplessInfo{delay, valid_frames}` per file; the reader
   already accepts it (verified: AAC boundary gap 887 frames -> 0).
5. **Sample rate:** shared mode streams are opened at the device mix rate and our decoder thread resamples with
   **rubato `Fft`** (MIT/Apache-2.0; measured 2000x realtime, 0.05 % of a core for 44.1 -> 48 kHz) using one
   continuous resampler across same-rate tracks. Exclusive mode opens at the file rate when the endpoint accepts it
   (bit-perfect) and reopens on a rate change. (The spike itself relied on the OS converter - `AUTOCONVERTPCM` - and
   had no resampler; same-rate tracks were gapless through it, loopback verified.)

## Evidence

### Gapless, seek, decode matrix (48 kHz; the 44.1 kHz set behaves identically except where noted)

"Boundary gap" is the silence/misalignment between the last real sample of file A and the first real sample of file B,
measured three ways: offline decode (`results/probe.txt`), callback output recording through the full engine
(`results/gapless.txt`), and **WASAPI loopback capture of the OS mixer** (`results/loopback.txt`). The three agree.
"Seek" = recorded output after a seek equals the reference sweep from exactly the requested frame
(max error vs reference after gain, `results/seekvol.txt`); offline seeks at 0, 12 345, ~2 s, 4 s, near end all land on offset 0.

| Format | Decode | Seek | Gapless (boundary gap) | Notes |
|---|---|---|---|---|
| WAV 16 / 24 / f32 | ok | exact | 0 frames, bit-exact | |
| FLAC 16 / 24 | ok | exact | 0 frames, bit-exact | Files from `flacenc` only (no libFLAC here). Symphonia rejected flacenc's STREAMINFO (`min_blocksize` = short last block, non-standard); patched in the generator. Expect libFLAC files fine; scanner must survive odd encoders. |
| MP3 CBR 192k **with LAME/Xing tag** | ok | exact (seek offset 0) | **0 frames** | Symphonia reads delay 1105 / padding from the tag. |
| MP3 CBR 192k, **no tag** | ok | consistent +1105 frames (decoder delay) | **+1059..+2295 frames (24..48 ms)** | Unfixable without metadata; most LAME/iTunes MP3 have the tag. VBR seek not tested. |
| ALAC 16 | ok | exact | 0 frames, bit-exact | Own minimal MP4 muxer (alac-encoder crate); not tested with Apple-produced files. |
| AAC-LC 192k (Windows MF encoder, MP4) | ok | exact | **+887 frames (18.5 ms) at 48 k, +931 (21.1 ms) at 44.1 k** from tail padding; **0 with external trim** | Symphonia: "AAC-LC gapless: No; ISO/MP4 gapless: No" (README, confirmed in source: `edts/elst` parsed, never used). MF output has no priming at all, so **iTunes/ffmpeg-style delay (1105/2112 frames) is the same bug at the head and was NOT reproducible here** (no ffmpeg on PATH). HE-AAC/SBR is not supported by Symphonia. |
| Opus, OGG Vorbis, AIFF, WavPack, APE, DSD | **not tested** | | | Symphonia lists Vorbis/AIFF; no Opus decoder. |

CPU is below the 15.6 ms tick resolution of `GetProcessTimes` over 20 s, so treat all CPU numbers as "under 1 % of a
core". Pure decode speed, single thread, 40 s stereo (`results/decspeed.txt`): WAV 5200x realtime, FLAC 1700x, AAC 1600x,
MP3 1200x, ALAC 640x. No Qt in the spike, so the RSS above is the audio stack only.

Position at 10 Hz: monotonic (0 backwards steps in all 34 runs), but quantised to the device buffer: the event-driven
backend moves in 10-20 ms steps, the measured deviation of position step vs wall-clock step is 12-14 ms (cpal) /
22-25 ms (direct WASAPI, buffer 20 ms). Four runs near an untrimmed track boundary (MP3 without tag, AAC without trim, both
backends) showed larger single deviations (32-95 ms); cause not investigated (the trimmed variants of the same files do
not show it). That is "frame exact at callback granularity", not sample-accurate at any instant;
`IAudioClock::GetPosition` (direct WASAPI only) can interpolate if a signal ever needs it. Seek *landing* is
sample exact.

### Options compared

| Option | Verdict | Why |
|---|---|---|
| Symphonia + own engine + **direct WASAPI** | **Recommended (Windows)** | Same gapless/seek results as cpal; 10 ms lower latency; stable start; exclusive mode (`ExclusiveModeToggled`); real device and endpoint-volume notifications; OS-specific module is what `architecture.md` already prescribes. Cost: ~300 lines of unsafe-free Rust on top of `wasapi`; macOS/Linux need their own module. |
| Symphonia + own engine + **cpal** | Recommended for macOS/Linux and as Windows fallback | Works, simplest, passed every test; but shared-mode only, higher and jumpier start latency, no volume/device notifications, no exclusive. |
| **rodio 0.23** (Symphonia + cpal) | Rejected | Gapless is fine (loopback: 0 frames for WAV/FLAC/MP3-tag/ALAC, same AAC/no-tag gaps), but `Source::next()` - i.e. file I/O and Symphonia decoding - runs **inside the cpal data callback** (`stream.rs init_stream`), violating the no-blocking/no-allocation rule; ALAC is not in default features; no exclusive, no device events, position is `Player::get_pos`. |
| miniaudio (C, MIT-0), FFmpeg/libmpv (LGPL/GPL), BASS (commercial), Media Foundation source reader | Not evaluated | FFmpeg/mpv conflict with "no large libs in every process" and licensing simplicity; miniaudio adds a C dependency for no gain over WASAPI; MF is a candidate **decode fallback for AAC/HE-AAC** (OS-licensed codec), see follow-ups. |

## Consequences

- We own the engine (ring, handshake, position, device switching). More code than "just use rodio", but it is the
  code that carries the project's core promises (never blocks, exact position, signals), and it is backend-agnostic.
- The signal pipeline gets what it needs: `pos_ds` from consumed frames minus latency; `Skipped`/`Seek*` from engine
  commands with exact from/to frames; `VolumeChanged` is raised by the UI gesture (the engine just applies the target);
  `SystemVolumeChanged`/`MuteToggled` from the endpoint-volume callback; `OutputDeviceChanged` and
  `ExclusiveModeToggled` from the backend open/close path.
- Library scanning must extract gapless info for M4A (`iTunSMPB`, `elst`) and keep it with the file record. Files
  without it are played untrimmed (documented limitation, same as every other player).
- Float -> integer conversion for exclusive mode: **TPDF dither** (2 LSB peak to peak) on `I16`/`I24In32` outputs,
  except for samples already exactly on the target grid, so 16-bit material through `I16` (or 24-bit through
  `I24In32`) at unity gain stays bit-perfect. `F32` and `I32` are never dithered. No noise shaping (T-0019;
  policy in `output/convert.rs`).
- Licensing: see below. MPL-2.0 (Symphonia) is file-level copyleft; we do not modify it, so no obligation beyond
  notices. AAC decoding in software has no patent license attached to the crate (Via LA licenses decoders/encoders
  sold in products; bitstreams are free). Tinwave is free local software but this needs a PO/legal decision; the
  Windows built-in AAC decoder is the zero-risk alternative on Windows.
- Mobile later uses platform audio APIs anyway (spec section 3); only the engine core, the reader and the resampler are
  portable, which is exactly the part worth sharing.

## Not verified (needs a human or other material)

- Device unplug, Bluetooth connect, default change by the user: engine reaction path (`switch_device` to a different
  endpoint and back) is verified; the OS events are registered but untriggered. `PO-RUNBOOK.md` has the procedure.
- Real-world files: no ffmpeg/iTunes/libFLAC on the machine, so AAC/ALAC/FLAC were produced by Rust crates and the Windows
  MF encoder. iTunes-style M4A priming, VBR MP3 seeking, HE-AAC and Opus remain unverified.
- 24-bit exclusive audible quality, ASIO, WASAPI offload, 5.1+ outputs (engine is stereo-only).
- Sample-rate change between tracks: verified on the fake output (T-0019: 44.1 -> 48 -> 44.1 -> 96 -> 48 kHz with no
  gap, no callback allocation), not yet listened to on a real endpoint. Exclusive mode still plays every track at
  the stream rate; reopening at the file rate is T-0057.

## PO and lead decisions (2026-11-02)

1. **D-0003 (PO): accepted.** `MPL-2.0` is allowed in `deny.toml` **only** for the `symphonia*` crates. Tinwave never
   patches Symphonia files in-tree: fixes go upstream, or around it in our own code.
2. **D-0004 (PO): AAC route decided later.** Symphonia AAC is used during development behind the same decoder trait;
   before any public release (spec §16 Phase 9 license review) AAC moves to the OS decoder where one exists
   (Media Foundation, AudioToolbox) unless the review says otherwise. T-0020 measures Media Foundation.
3. **Lead: untagged MP3 keeps its 24–48 ms gap.** No delay heuristic; a guessed trim could cut real audio.
4. **Lead: device following vs. signals.** The playback output registers its own `IMMNotificationClient` only to
   re-open the stream; all device and system-volume *signals* come from `tinwave-context` (ADR 0004). Turning off T1
   device context therefore never breaks device following.
5. The test-only encoders used by the spike (incl. `mp3lame-encoder`, LGPL-3.0) must never enter the shipped tree;
   `cargo deny` on the workspace enforces it.
